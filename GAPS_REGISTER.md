# Gaps Register — honest scope accounting

Two kinds of entries: **scope cuts** (what I chose not to build or finish, and why) and **data anomalies** (what I
found in the provided pack and what the system does about it). Counts are from `brahmo setup` on the pack as given.

## A. Scope cuts and known limitations

| # | Gap / cut | Where | Why I chose this / what I'd do with more time | Risk if left |
|---|---|---|---|---|
| A1 | LLM-assisted mapping is a suggestion hook, not exercised | `normalize/resolver.py` (`llm_assist_enabled=false`), D-024 | No API key in the build environment; the deterministic funnel already handles the pack. With a key: propose candidates for `FUZZY_ONLY`/`UNKNOWN_BRAND` items, land them in the queue as `LLM_SUGGESTION_UNVERIFIED`. | Reviewer throughput on typos (19 stock rows, RX08) stays manual. |
| A2 | Alias table has a mechanism but no learned rows | `brand_alias`, D-003 | Rows should come from review decisions, not from me guessing. A `brahmo review --accept` command is the next step. | Same billing typo is re-queued per batch until aliased. |
| A3 | Module B LLM mode untested against a live model | `rag/answer.py` `llm` mode, `prompts/runtime/` | Guard logic is unit-tested with synthetic claims; the end-to-end path needs `ANTHROPIC_API_KEY`. Extractive mode is the shipped default and passes 11/11. | Readability of answers for doctors; none for correctness (guard drops unverifiable claims). |
| A4 | Semantic leg is a hashed n-gram embedding, not a transformer | `rag/embeddings.py`, D-015 | Fresh-machine reproduction without downloads; on 83 units the difference is immaterial. `sentence_transformers` is a config switch. | Paraphrase recall on a large corpus; no effect on this pack (eval 11/11). |
| A5 | No doctor-facing rendering, no multi-tenant separation, no freshness watcher daemon | stretch items | Core gates first; freshness is enforced by windows (`DATA_EXPIRED`) rather than by a watcher. Part 2 §1 designs all three. | None for Part 1 gates. |
| A6 | Decomposition relies on the extract's structured columns | `ingest/cdci.py` | The pack provides ingredient/strength columns; `strength_text` is cross-checked (0 disagreements). A free-text-only source would need the `strength_text_parse` method path, which exists but is only used for cross-checking. | G2 on a held-out key depends on the extract's own correctness (e.g. Thyronorm "50 mg"). |
| A7 | Freshness windows are placeholders (400 days) | `config/settings.json` | A clinical/regulatory owner sets these; I made them explicit config with a note rather than guessing policy. | A stale register could pass as fresh for longer than policy wants. |
| A8 | Reference ceilings contain one entry (paracetamol, adult) | `config/reference_ceilings.json`, D-011 | Only ceilings the corpus itself states are allowed. | CUM-001 reports totals "without judgement" for every other ingredient (RX09). Intended. |
| A9 | Interaction check reports `PARTIAL_COVERAGE` for ingredients outside the 15-pair seed | D-010 | Honest coverage; the alternative claims a screening that did not happen. Raised in Day-2 Q&A. | Held-out scoring counts these as 0 rather than +1 if the graders expected `CHECKED_NO_HIT`. |
| A10 | Review queue has no UI and no resolve/accept workflow beyond SQL | `review_queue` | Out of Part 1 scope; `brahmo review --list` exists for inspection. | — |
| A11 | Patient population is an optional input, not derived | rail input `patient_population` | Deriving age from a transcript is Phase C (patient context); without it ceilings are "not confirmed". | More `PARTIAL_COVERAGE` than necessary on CUM-001. |
| A12 | ~~Single data batch per dataset; no "current batch" pointer~~ **Closed by D-027**: every check now reads only the latest batch per dataset. | D-027 | — | — |
